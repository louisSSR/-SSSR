# 白 · 蝴蝶效应 v1.1.1

原生 SillyTavern 扩展：白与 Q 版白主题、随界商店、因果账本、委托派发、四类长期记忆，以及独立的数据库皮肤。

## 安装与升级

1. 先在旧商店“本源与连接”导出完整账本，关闭其他酒馆标签页。
2. 将本包 `shiro-butterfly-shop` 目录复制到 `SillyTavern/data/<用户>/extensions/`。已有同名目录时覆盖插件文件，保持目录名不变。默认单用户为 `data/default-user/extensions/`。
3. 刷新页面启用“白 · 蝶翼商店”。原有账户、余额、交易和所得仍保存在原浏览器、原酒馆地址，不需要重新建本源。
4. 本包不覆盖 `shujuku` 文件。官方数据库可按自己的方式更新；白主题保存在商店目录，开关保存在酒馆扩展设置中。
5. 如果你安装过旧包中的 `1.2.5-shiro.1` 数据库兼容版，恢复官方版本前先备份扩展文件和聊天数据。目录存在自定义修改时，不要盲目丢弃 Git 修改；参见 `docs/database-update-contract.md`。

未安装到你的现用酒馆。本包不含聊天、用户数据库、API 密钥或测试服务器资料。

## 手机版（v1.1.1）

同一插件包同时适配手机和电脑，无需另装移动版。插件安装在运行酒馆的设备或服务器上，手机浏览器连接该酒馆即可打开手机版界面。手机顶部导航可左右滑动；点击栏目会回到该页开头。商品采用单列、四表按记录分块显示，精确金额保留完整数值并自动换行；完整交易表仍可在表格内部左右滑动。

触控按钮和输入框加大，弹窗内独立滚动。浏览器上报可见区域变化时，界面会随地址栏、横竖屏和软键盘调整；插件不另行禁止系统捏合缩放，能否缩放沿用酒馆页面自身的设置。数据库原生按钮、输入和手机编辑布局同步调整，打开手机数据库时，悬浮商店入口会自动让开保存区，关闭数据库后恢复；仍可从数据库内的“四表／委托”快捷入口进入商店。

手机浏览器仍使用酒馆原来的安装与数据保存方式；从电脑换到手机时，请在电脑导出完整账本，再在手机恢复。手机浏览器本地数据不会自动继承电脑浏览器数据。不同手机系统的实际键盘与浏览器行为，以使用时表现为准；本次设备覆盖见验收记录。

## 白主题

默认开启。在酒馆扩展设置或商店“蝴蝶表格”页可以切换“白 · 空白棋局数据库主题”。包含独立页头、Q版白、棋盘纹理、冰蓝淡紫配色、侧栏、表头、按钮和选中状态。关闭会还原数据库原有外观。数据库侧栏白卡可直接打开同一本源的“四表记忆”和“白的委托”。

主题不改原生数据库数据和文件。已验证原版 1.2.5；将来上游改变界面结构时，无法识别的界面会保持原样，可能需要更新本插件的主题适配，不能保证未知版本永远免维护。

## 白的委托

连接已配置的酒馆 API，打开聊天和商店本源，在“白的委托”输入方向并选择“让白派发任务”。每次最多整理三项，关联当前世界、人物与未结束的连锁反应。

委托先待接取，可接受或搁置。实际目标在故事中成立后，点“核对实际完成情况”；程序要求对应本轮真实因果结果和原文证据。任务状态关联结算事件，派发、接取、完成状态本身不额外发点，不会在因果结算之外再领一次奖励。已完成和已搁置任务保留历史。

## 四类记忆

| 表 | 保存什么 | 给 AI 的用途 |
| --- | --- | --- |
| 重要印象 | 人物、势力、承诺、重大选择及证据；支持手动确认、优先保留 | 保持人物与关系连续性 |
| 点数账目 | 精确余额、累计入账、累计消费，以及相关已结算结果 | 不凭剧情重置或乱算点数 |
| 消费与所得 | 购买、持有、实际消耗、移交与跨界权益 | 记住已经支付和获得的内容 |
| 连锁反应与任务 | 因果来源、已结算部分、待观察后续、当前委托 | 让后续剧情承接之前的选择 |

完整历史保存在本地本源账本。四表是按当前剧情和关键词选出的阅读摘要，不删除或覆盖原档案。同一人物的新印象优先进入摘要，旧版本保留。从本版起，连锁反应每次发生实质更新也会归档旧版本；旧版已经覆盖掉的更早文本无法凭空恢复。可用“召回相关记忆”检索旧人物、能力、世界或事件；重要印象可手动优先保留。记忆预算有限时不可能把无限历史全部同时发给 AI，页面会显示未展开数量。

商店内四表与任务、点数、交易共用同一份档案；数据库白卡的入口打开这份最新记录。“导出数据库四表”输出当前摘要的原生导入文件，是快照，之后要重新导出导入刷新。四表原生导出默认关闭世界书注入，并将原生自动填表频率设为 0，避免同一份记忆发送两次或被填表模型改写。不要自行开启原生全表额外注入，也不要在手动填表时选择这四张只读快照表。若以前导入过旧六表，请在每张旧表的原生参数里把“更新频率”设为 0，并保持世界书导出关闭；升级插件文件不会擅自改动你已有表格的设置。若此前另外复制或外部导入了蝴蝶世界书条目，请单独停用重复条目；新开关不会自动删除或禁用那些副本。

旧六表是完整账务归档，仍可导出。只有原有、已核验的聊天绑定兼容桥才自动写回旧六表；官方原版没有这个接口，更新后自动原生写回会暂停，商店和独立四表继续工作。不会用可能写错聊天的接口强行同步。

## Token 控制

- 剧情记忆默认上限 **2048 Token**，可选 4096 / 8192。每次用当前酒馆分词器计数并缩小摘要，显示计数和未展开记录数。计数不可用时采用严格 UTF-8 字节预算兜底，不把错误的 0 当作成功。
- 持久历史不逐轮完整发送。永久金额保持精确；重要、相关、近期内容优先；未展开的所得仍有效。
- 商店/委托/结算评估只发送相关账本摘录；本插件请求文本最多 8000 Token（或保守字节计数），超出会继续压缩，仍不通过则停止调用，不发超限请求。
- 此预算只覆盖本插件增加的文本。角色卡、聊天历史、其他世界书、模型响应以及数据库原生操作使用酒馆自己的上下文配置；本插件不能保证整场对话总 Token 永不超限。宿主的某些分词器会估算计数；数据库 API 预设若使用另一种模型，宿主计数也只作估算，不能冒称该模型的精确分词结果。

## 账本与备份

同一酒馆登录用户、同一本源跨世界延续，初始余额为零；1点固定本源增益常驻。购买按完整八项规格与固定报价成交，点数和所得原子保存；模型不能自行购买。因果只计实际已成立的新作用，未来只追踪，既有收益不追扣。

“导出完整账本”包含原有账务以及新增印象、委托历史。旧 v1 备份仍可导入；恢复建立独立本源，避免覆盖现有历史。新增记忆字段的备份请使用 v1.1.0 或更新版恢复，不向旧插件降级导入。换浏览器、清理站点数据或换酒馆地址前先备份。

同义事实的完全自动识别仍依赖模型判断；程序只对稳定ID和规范化后的相同事实做严格去重，不承诺任意换词都能识别。报价、计功参照和证据保存在全量档案参与校验。
