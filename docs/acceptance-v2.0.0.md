## 真实宿主

隔离SillyTavern1.18.0、酒馆助手4.8.18、未修改官方数据库1.2.5 SQLite。无用户真实卡文或付费AI调用。

较早构建ae7ccd11（编码修复前）未包装getContext的正常7案通过：四表初始化、同批更新、购买3瓶、用1瓶、移交1瓶、任务完成引用实际事件不重复计功、聊天冷重载后账本一致。每次验证真实服务器聊天回读。详细结果 public-api-host-unwrapped-result.json。

受控保存切换实验使用仅观测/暂停的getContext.saveChat外壳，最终调用原样core.saveChatConditional。立即切聊天可使上游API返回success/saved=true却无目标A账户保存；暂停保存前切换的结果依时序变化，观察中B未混入A账户。插件还需检查scope、四表往返及服务器帧，不把上游标志单独当到账依据。真实race实验不等于跨设备CAS。

当前最终商店构建 cb2566ad、主题 b48e788d，真实宿主正常路径9/9通过。真实安装的最终商店通过显式原生刷新、连续保存重要印象与冷重载回读；当前横竖数据库面板和正向头手探头见 canonical-final-refresh-host-result.json。正常 UI 路径未包装 getContext，使用实际扩展加载器和酒馆助手全局脚本运行。

最终源码的两项受控真实宿主验证2/2通过，见 maintained-targeted-host-result.json：保存边界 A→B 后原生事务拒绝，B 不含 A 账户或该新记录；一次宿主保存拒绝后，API不返回 saved=true，仓库 read/list 暂停，后台没有失败记录，真实 UI 没有成功提示。这两项存在明确的 trace/barrier 或故障注入，不与未包装正常 UI 路径混算。

切换 B→A 后，官方写入 provider 可能仍为空B上下文，尽管公开只读查询与导出是A。只读诊断插桩已确认这一差异，严格CAS正确拒绝覆盖。诊断后恢复原官方构建；公开 refreshDataAndWorldbook 重载可恢复。商店“重新载入 / 核验保存”现调用该接口并重新检查聊天身份与服务器帧；背景读取保持只读，失败交易不自动重试。

独立官方模块冷加载实验确认裸数字TEXT会丢金额精度与前导零（修复前13处字段差异）。最终版本对纯数字及保留前缀原文作显式可逆编码，原始存储字节继续参与严格CAS，业务显示还原原文；修复后完整字段、两次业务更新及再次冷加载均为0处差异。该实验采用官方模块与明确模拟宿主，不冒充真实浏览器交易证据。

## 安装与边界

Git本版在 fix/native-four-tables-mobile-2.0 分支，尚未合入main。新安装填仓库 https://github.com/louisSSR/-SSSR.git 和此分支名；已有扩展在管理页面切换分支，或使用交付ZIP。

先备份旧账本和数据库。在官方数据库左上名称连续点5次开启进阶模式，再在仪表盘→高级设置选SQL（SQLite），保存重载。安装v2四表时保留其它表，保存后关闭原生窗口，再在商店初始化或显式恢复。数据库导入重建ID时按精确表名、全部列和DDL核验实际身份。

SQL查询探针缺能力时停止写入，默认native/DSL模式不能作为事务运行环境。浏览器须支持WebLocks；只有同源标签串行，不保证不同设备同时改同一聊天的服务器CAS。官方聊天加载与模板切换仍可能重建空运行时，校验会拒绝而非自动重试；等原生加载完成、重新载入后核对四表。

实体iOS/Android系统键盘、跨设备并发、真实模型语义质量和用户对造型的接受未自动验证。driverAccepted=false。测试期间TTS语音列表接口400属于未配置语音探测，不是四表保存失败。日用酒馆未安装/改动。
