# 白 · 原生四表与手机版交付

版本：商店2.0.0、独立主题1.3.0、四表schema v2。日期2026-10-09。

插件管理原生重要印象、点数账目、消费与所得、连锁反应与任务；每聊天唯一独立本源，同一聊天跨世界保留全部权益。旧 IndexedDB 仅显式只读导出，恢复只允许目标空四表，不合并或覆盖历史。没有直接改余额入口。

主题、Git插件和四表模板是三份交付。主题不再复制四表；收起白是独立正向头部与双手，展开保留六态身像。手机布局使用可见视口、内部滚动和键盘避让。商店48px入口拖动、5秒吸边半隐，最小44px屏内热区。

## 自动与独立实验

- 商店维护测试150/150；主题正式构建测试32/32；两组件TypeScript与正式构建通过，四表空模板可重复生成。
- 官方SQLite严格冷帧回放16步，含创建、计功、报价、购买、使用、移交、印象、余波、任务与完成；每步完整账本相等。
- 手机Chrome夹具192四边探头、3实际触摸/拖动尺寸、9长表与可见视口场景通过；是浏览器证据，非手机实机。
- 独立双API缓存/共享后端复现及修复：旧标签写前拒绝、稳定avatar/group聊天身份、原生源失效清旧UI/注入、未确认保存的业务读取暂停。

## 真实宿主

隔离SillyTavern1.18.0、酒馆助手4.8.18、未修改官方数据库1.2.5 SQLite。无用户真实卡文或付费AI调用。

未包装getContext的正常7案通过：四表初始化、同批更新、购买3瓶、用1瓶、移交1瓶、任务完成引用实际事件不重复计功、聊天冷重载后账本一致。每次验证真实服务器聊天回读。详细结果 public-api-host-unwrapped-result.json。

受控保存切换实验使用仅观测/暂停的getContext.saveChat外壳，最终调用原样core.saveChatConditional。立即切聊天可使上游API返回success/saved=true却无目标A账户保存；暂停保存前切换的结果依时序变化，观察中B未混入A账户。插件还需检查scope、四表往返及服务器帧，不把上游标志单独当到账依据。真实race实验不等于跨设备CAS。

## 安装与边界

先备份旧账本和数据库。在官方数据库左上名称连续点5次开启进阶模式，再在仪表盘→高级设置选SQL（SQLite），保存重载。安装v2四表时保留其它表，保存后关闭原生窗口，再在商店初始化或显式恢复。数据库导入重建ID时按精确表名、全部列和DDL核验实际身份。

SQL查询探针缺能力时停止写入，默认native/DSL模式不能作为事务运行环境。浏览器须支持WebLocks；只有同源标签串行，不保证不同设备同时改同一聊天的服务器CAS。官方聊天加载与模板切换仍可能重建空运行时，校验会拒绝而非自动重试；等原生加载完成、重新载入后核对四表。

实体iOS/Android系统键盘、跨设备并发、真实模型语义质量和用户对造型的接受未自动验证。driverAccepted=false。测试期间TTS语音列表接口400属于未配置语音探测，不是四表保存失败。日用酒馆未安装/改动。
