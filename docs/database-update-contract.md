# 数据库、主题与蝴蝶插件的独立更新

三份交付分别安装，也分别更新：

| 交付 | 安装方式 | 更新影响 |
| --- | --- | --- |
| 木偶白数据库主题脚本 | 酒馆助手的全局脚本库导入 JSON | 外观、手机布局、本地玩笑及可选实时四表视图 |
| 白·蝴蝶效应商店 | 酒馆扩展管理中安装或更新 `https://github.com/louisSSR/-SSSR` | 商店、任务、账本、预算记忆与只读四表服务 |
| 蝴蝶效应原生四表 JSON | 空模板在数据库“表格模板”导入；完整快照的数据接口另见四表说明 | 建立空表或保存完整业务记录；模板导入不等于完整记录恢复 |

原数据库继续从自己的来源更新。这些交付不覆盖数据库程序，不安装旧补丁，不改原生保存接口。已验证基线为 SillyTavern 1.18.0、酒馆助手 4.8.18、官方数据库 1.2.5；上游改变界面结构或 API 时仍需适配，不把这一基线冒称永远兼容。

## 更新操作

1. 在商店导出完整本源账本；另外备份原数据库模板和表数据。
2. 在原商店安装目录检查更新并刷新，保留原目录和 `.git`。不要另装第二份同名商店。
3. 在酒馆助手停用旧白主题脚本，再导入新版 JSON，确认新开关已开启；若关闭再打开。若还装有早期的 `shiro-database-theme` 扩展，也先停用。
4. 原数据库按自身流程更新。商店的稳定身份、IndexedDB 名称、登录用户及本源作用域保持不变。

停用主题恢复原数据库外观，商店仍可使用。停用商店清除其记忆注入及四表订阅，主题仍可使用。更换素材或主题配色无需重装四表。

## 数据库内实时四表

新版主题读取商店公开的只读四表服务，在数据库界面内查看重要印象、点数账目、消费与所得、连锁反应与任务。记录来自已提交的同一本源；完成交易或更新任务后重新读取。查询和分页不删除档案。

服务返回聊天、登录用户、本源账户及账本版本。切换身份或停用插件时，视图清除旧数据；迟到的读取不能进入新视图。主题不写点数、完成任务或调用模型，相关操作仍由商店提交。

这是真实的插件四表视图，不是官方数据库内部历史的自动写回。完整原生四表 JSON 是独立快照；数据库 1.2.5 的模板入口把行作为初始化数据，完整记录恢复需先注册对应模板、匹配实际表 ID，再使用数据接口并核对读回。详见[四表说明](four-tables-install.md)。两者明确区分，不将模板或静态快照冒称实时联动。

## 历史、原生四表和 Token

空模板文件内固定 ID 为 `sheet_shiro_memory_1` 至 `sheet_shiro_memory_4`，原生应用后可能重建；文件不含虚构点数或用户资料。“导出数据库四表”输出完整四类业务记录；“备份完整档案”还包括全部固定报价、计功参照和交易权益。

每轮发给 AI 的摘要与完整导出分开：默认预算 2048 Token，保留精确财务汇总并选入相关印象、所得和任务。分词器失败或超时采用保守 UTF-8 字节上限，不当作零用量。完整档案保存在本地，省略的记录没有失效。

原生四表默认关闭世界书导出、世界书注入和自动填表，避免再发送一份。不要手动将这些表选为 AI 填表目标；以前复制进世界书的快照也需自行关闭。插件预算只约束插件新增文本，不替代其它世界书和角色卡设置。

## 旧六表

`butterfly-tables.json` 是旧六表归档。其自动写回依赖曾核验的 `acu-chat-bound-projection/1` 补丁协议；官方原版没有该协议，该入口保持关闭。本版实时四表、独立导出和账本不依赖旧桥。

不要为本版覆盖官方数据库、安装旧补丁或并排启用两套数据库。手动修改原生快照数字不会修改商店余额或补发物品。
