# 数据库、主题与蝴蝶插件的独立更新

从商店 v1.2.0 开始，三份交付互相区分：

| 交付 | 安装位置 | 更新影响 |
| --- | --- | --- |
| 完整白／Q版白数据库主题 | `extensions/shiro-database-theme` | 只更新外观、手机布局和可选快捷入口 |
| 白·蝴蝶效应商店插件 | `extensions/shiro-butterfly-shop` | 更新商店、任务和记忆；沿用原本源账本身份 |
| 蝴蝶效应四表 JSON | 通过数据库原生模板入口导入 | 只建立表结构或手动更新导入快照 |

原版数据库 `shujuku` 继续从其原有来源更新。两个自有扩展不覆盖数据库源码，也不改变原生保存接口。将来上游改变界面结构时，主题可能需要重新适配，不能预先保证任意新版本兼容。

## 从 v1.1.1 升级

1. 在商店导出完整本源账本；另外导出数据库原生模板与表数据。
2. 更新同名 `shiro-butterfly-shop` 目录到 1.2.0。插件的稳定身份、IndexedDB数据库名和用户／本源作用域不变。
3. 单独安装 `shiro-database-theme`。不要同时运行旧商店内置主题和新独立主题；先更新旧商店，再启用新主题。
4. 独立主题首次读取旧商店的外观开关作为默认值；此后主题设置保存在自己的命名空间，双方不互相覆盖。
5. 主题和商店都启用时，数据库主题显示四表／委托快捷入口。停用商店后，这些入口移除，主题仍保留；停用主题后数据库恢复原外观，商店仍可打开。

只需要白数据库外观时，单装主题即可；原生“导入主题”JSON只提供配色，完整角色图片和布局来自独立主题扩展。手机上的商店悬浮按钮避让原生数据库保存区不依赖主题。

## 四表与数据来源

独立空模板 `butterfly-memory-four-tables.json` 的表格身份固定为 `sheet_shiro_memory_1` 至 `sheet_shiro_memory_4`。它不包含用户数据，不会自动写入点数或发放物品。商店内四类记忆从唯一的本源账本生成，预算和长期档案规则沿用前版。

“导出数据库四表”产生当前摘要快照；要在原生数据库中看到更新，需要重新导出、导入。模板不是双向实时同步桥，数据库中手动修改的余额不会回写商店。详见 [四表导入说明](four-tables-install.md)。

四表默认同时关闭世界书导出与注入，自动填表频率为0，避免重复发送。此默认值不限制用户手动填表操作，也不会删除以前复制到世界书的条目。请不要把四表选为手动填表目标，不要额外打开重复注入。商店Token预算只覆盖插件新增文本。

## 旧六表与原版边界

`butterfly-tables.json` 为旧六表归档模板，独立四表文件不替换它。旧六表自动写回严格依赖 `acu-chat-bound-projection/1` 与已核验的补丁版本。官方原版1.2.5没有该协议，因此原生自动写回保持关闭；不能依靠一次聊天ID比较，绕过异步提交的聊天绑定风险。四表导出和独立账本不受此影响。

如果仍使用早期 `1.2.5-shiro.1` 数据库补丁版，恢复官方版前保留扩展、设置、聊天及本源备份，确认实际目录、远端和本地修改。没有Git记录的补丁目录不具备官方仓库的更新身份。不要同时启用两套数据库，也不要直接丢弃未知本地修改。上述恢复操作没有在用户日常实例执行。
