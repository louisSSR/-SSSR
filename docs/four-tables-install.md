## 查看最新记录

同时启用新版商店和木偶白主题脚本，打开数据库的“蝴蝶四表”。这里读取当前已提交本源；接取委托、记录印象或消费后会刷新。可以查询和翻页，当前页未显示的记录仍存账本。没有商店或没有已选本源时会显示相应提示，不编造示例余额。

这份实时视图和每轮给 AI 的摘要使用同一账本。它不改官方数据库内部数据；主题停用后，商店仍能查看四表和导出 JSON。

## 独立导入原生四表

`butterfly-memory-four-tables.json` 是空模板，只有表头，不含账户、剧情、余额或示例记录。

1. 备份当前数据库模板及表数据。首次导入建议先在新聊天中操作。
2. 数据库“表格模板”→“导入模板 JSON”，选择空模板。
3. 按原生提示保存／应用。已有其它表格时，使用数据库原生合并流程保留；不能假定覆盖导入会保留旧表。
4. 核对四张表的名称和表头。内部 ID 可能重建，按表名和表头核对即可。

数据库 1.2.5 的模板导入会将文件中的数据行移为初始化数据 `seedRows`，不能用它直接恢复全部运行记录。空模板建表、完整记录导出和实时视图是三件不同的事。

完整四表文件是生成时的独立数据快照。数据库 1.2.5 的完整数据接口是 `await AutoCardUpdaterAPI.importTableAsJson(jsonText)`，参数为 JSON 字符串，返回布尔结果；返回 `true` 只证明导入提交，不能证明当前模板会显示全部记录。这是维护者接口，使用前备份并选择专用目标聊天；它会覆盖目标原生表，不会自动合并四张表。

已验证的维护者恢复范围是新建专用目标聊天：先建立空四表，目标尚无既有原生 V2 表数据历史，并有可保存的助手消息楼层。已有数据或反复切换过模板的目标不在此恢复保证内，须保留备份，不能只凭接口返回成功覆盖原聊天。先按上述原生界面流程应用空四表模板，确认当前聊天已注册四张表。原生导入可能按名称重建表 ID：读取当前 `AutoCardUpdaterAPI.exportTableAsJson()` 返回的对象，按四个唯一表名和相同表头匹配目标表，将快照的四个表键及各表 `uid` 映射到实际目标 ID，再把转换后的 JSON 字符串交给数据接口。仅转换表键／`uid`，不要修改单元格、业务记录 ID 或设置；遇到重名、缺表、表头不一致或目标还有其它表时先停止。导入后再次导出，核对四类记录数、点数和记录内容，并保存／重载确认。原文件应保留不动。默认其它模板可能筛掉未注册的表，不能跳过建表和身份匹配。

原生界面没有裸 `chatSheets` 文件的完整数据导入按钮；“导入 Checkpoint”要求另一种完整检查点包装，不能直接放入此文件。

普通使用者从数据库里的实时四表查看最新业务，无需反复导入。数据接口导入的原生快照不会继续同步，也不反写商店账本。

完整四表导出包含四类业务记录；可恢复的完整档案还包括固定报价、计功参照等。换手机、浏览器或酒馆地址前，应导出完整档案备份。

## 避免重复发送

四表分别关闭“导出到世界书”和“注入世界书”，自动更新频率为 `0`。这些是不同开关，不能只关一项。

商店按预算发送相关四类记忆，默认 2048 Token；分词失败采用保守字节计数。完整导出与表格分页不扩大每轮摘要，这个预算只覆盖本插件新增文本。

原生快照的“只读”是使用约定，不是编辑权限锁。不要选它们手动 AI 填表或另开重复注入；旧世界书条目不会因导入自动删除。手改原生余额不会修改商店账本。

## 文件身份

空模板与完整导出文件内的四张表 ID 为 `sheet_shiro_memory_1` 至 `sheet_shiro_memory_4`；原生应用模板后可能生成其它 ID，不能假定保持不变。不通过改表头换肤，外观由独立主题处理。`butterfly-tables.json` 是另一份旧六表归档。

维护者用 `npm run tables:check` 核对空模板、`npm test` 核对投影与业务规则；原生导入仍须在目标版本真实验证。
