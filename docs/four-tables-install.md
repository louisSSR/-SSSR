# 原生四表 v2：安装、读取与恢复

四表是业务数据来源。插件读取业务列并验证完整历史，通过原生公开 SQL 批次提交变化。

数据库必须使用 SQLite 模式。官方 1.2.5：连续点击左上数据库名称 5 次开启进阶模式，在仪表盘 → 高级设置中选择 SQL；按原生提示保存并重新载入。默认 native 模式无法提交本版事务，插件会在写前暂停并给出提示，不自动修改数据库设置。

1. 备份原数据库模板、表数据及旧完整账本。
2. 在指定聊天的原数据库模板页面安装四张蝴蝶表，保留其它表，不以四表文件覆盖全套模板。
3. 保存应用，关闭编辑器，返回商店刷新。
4. 初始化空四表或显式恢复完整备份；两者只允许空四表。

空模板 butterfly-memory-four-tables.json 无账户、余额、剧情及示例。官方 1.2.5 导入会重建表键和 uid；插件按唯一精确表名、全部列头、DDL 和所有权说明核验实际身份。缺表、重名、旧 v1 快照或结构损坏时拒绝写入，无需手工修改 ID。

| 表名 | 业务内容 |
| --- | --- |
| 蝴蝶·一、重要印象 | 全部印象和依据 |
| 蝴蝶·二、点数账目 | 账户、全部交易、计功及固定标准 |
| 蝴蝶·三、消费与所得 | 全部固定报价和所得，含未买商品 |
| 蝴蝶·四、连锁反应与任务 | 余波、历史版本和任务 |

金额为精确十进制 TEXT，余额由交易推导，没有自由修改余额列。财务和已结算历史只追加，固定规格不回改。

## 备份与迁移

“完整账本备份”可恢复全部历史。“完整四表”供原生业务检查和另存；普通恢复使用商店备份入口，不调用覆盖全原生表的 importTableAsJson。

每段聊天独立，同一聊天内换世界保留本源。旧浏览器账本不自动合并；手动查找并导出指定旧备份，然后显式恢复到指定空四表。原件未修改。旧 v1 四表摘要缺少完整报价和权益链，不能冒充完整账本。

## Token 与更新

四表默认关闭世界书导出、注入和自动填表。插件摘要默认 2048 Token，省略不会删数据。不要将全文再次注入或选作自动填表目标。原生编辑器打开时暂停商店写入，未保存更新须先核验。

主题只处理外观，原数据库继续自行更新。旧六表和旧快照请备份后停用，不作为 v2 来源。模板重新导入后的数据保存与真实宿主边界见当前验收记录。
