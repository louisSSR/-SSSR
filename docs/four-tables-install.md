# 蝴蝶效应四表：独立导入说明

`butterfly-memory-four-tables.json` 是可单独导入数据库的空白四表模板。文件没有账户、余额、剧情或示例记录，也不包含插件和主题。它与商店“导出数据库四表”使用相同的表格身份和列结构。

| 表格 | 用途 |
| --- | --- |
| 重要印象 | 查看人物、世界与已确认的最新印象。 |
| 点数账目 | 查看精确余额、累计收入、累计消费及选入摘要的已计功记录。 |
| 消费与所得 | 查看购买所得、持有／使用／移交状态及已消费点数。 |
| 连锁反应与任务 | 查看余波追踪、任务目标与完成状态，供剧情承接。 |

## 导入空白模板

1. 在目标聊天中打开数据库，先导出备份当前模板和表数据。模板导入／切换可能影响当前聊天使用的整套表格，因此第一次建议在新聊天中操作。
2. 进入数据库的“表格模板”页面，选择“导入模板 JSON”，选择 `butterfly-memory-four-tables.json`。
3. 按原生页面提示保存／应用到目标聊天。确认显示上述四张表，且每张表只有表头，没有虚构的起始点数。
4. 如果已有其他表格，使用当前数据库提供的模板合并／编辑流程保留它们。此文件不保证自动合并，也不要用“覆盖全部表”导入来尝试保留原表。

这份模板沿用已核验的龙血玄黄·数据库 1.2.5 原生 `ChatSheets` 格式。不同版本的菜单名称或导入行为可能变化，应以实际导入预览与提示为准。

## 用商店数据刷新四表

空白模板本身不会生成点数、派发任务或从聊天自动采集记忆。使用“白·蝴蝶效应”商店插件建立或接续本源后，打开“四表记忆”，点击“导出数据库四表”。将新导出的 JSON 经数据库原生导入流程应用到需要查看的聊天。

**插件内四表随本源档案更新；原生数据库中的四表是导入时的快照，需要重新导出、导入才能刷新。** 原版数据库的四表不会由商店自动写回；旧版兼容桥的六表同步也不会把这份四表模板变成实时同步表。

这四表用于展示与阅读。完整历史、交易与权益以商店的本源账本为准，数据库里手动改数字不会修改商店余额或补发物品。“导出数据库四表”仅导出当前摘要；如需完整可恢复备份，请使用商店的“备份完整档案”。

## 控制每轮发送量

四张表默认分别关闭“导出到世界书”和“注入世界书”，并将自动更新频率设为 `0`，避免数据库自动填表又发送一份记忆。它们是不同开关，不能只关闭其中一项。

商店自身负责按预算整理并发送四类记忆，默认预算为 2048 Token，完整历史仍保存在本地。本模板单独导入时不会替代商店的预算功能，也不控制其他世界书、聊天记录或角色卡的 Token 用量。

“只读”是这套表的使用约定，不是禁止手动编辑的权限锁。原生界面若让你手动选择表格填充，仍可能把它发给 AI；不要把这四表选为手动填表目标。若以前已将旧快照复制到世界书，需要自行关闭对应旧条目的注入；导入本文件不会自动删除历史条目。

## 文件身份与维护

JSON 文件中的固定表格 ID 为 `sheet_shiro_memory_1` 至 `sheet_shiro_memory_4`，与商店导出一致。原生数据库导入时会按表名重新生成内部 ID，因此导入后应按上述四个表名与表头检查，不要求内部 ID 保持原样。不要手动更改导入文件的 ID 或表头来实现换肤；外观由独立主题处理。`butterfly-tables.json` 是另外的旧六表模板，不是本文件。

维护者可在含项目依赖的源码目录中运行：

```text
node extensions/shiro-butterfly-shop/database/generate-memory-four-tables.mjs --check
node --test extensions/shiro-butterfly-shop/tests/four-table-template.test.mjs
```

如插件导出结构变更，先运行生成脚本的 `--write`，再运行检查和原生导入验证。生成脚本复用商店当前的四表导出函数，不读取浏览器或用户账本。
